# 普通浏览器下载与自动入库（0.7.0）

0.7.0 继续使用日常默认浏览器下载论文，再检查用户配置的本地文件夹，并新增下载诊断、重查已下载文件和候选 PDF 预览核对。只安装 Zotero 插件，不需要 Edge 扩展，也不需要浏览器调试端口。当前版最终测试、实际安装包与正式文库更新状态以 [0.7.0 验收记录](verification-v0.7.0.md) 为准，分发采用私有草稿预发布流程。0.5.0 和 0.6.0 的实测记录保留原版本归属，不视为当前版本重新验收。

## 一次下载怎样完成

1. 在 Zotero 中选择文献并使用全文助手。网页自动获取仍未取得全文时，在对应任务点击 **浏览器下载并自动入库**。
2. 插件先停止该任务的旧获取并等待清理，记录配置目录中已有 PDF 的大小与修改时间，开始检查新文件，然后使用 Windows 默认浏览器打开论文。默认浏览器是 Edge 时，使用的就是日常 Edge 及其自身登录状态。
3. 用户自行完成网站登录、验证码和下载操作，把 PDF 保存到配置的任一文件夹。插件不会点击页面中的下载按钮，也不会读取或控制浏览器标签页。
4. 文件完成写入且身份明确匹配后，插件将 PDF 添加到原文献。当前批次的任务进入 **已获取**，也会出现在跨批次的 **全部历史**，来源显示 **浏览器下载**；已有有效 PDF 会被复用，避免重复附件。文件未自动入库时，展开任务的 **下载检查详情**，按下文说明查看原因或核对候选。

网站是否允许访问、浏览器是否成功下载仍由当前网站和用户的访问权限决定。浏览器流程不会自动发起新的科研通求助。

## 任务范围、语言和复制

**进行中、需网页登录、待兜底、已获取** 只显示最近一次批量操作涉及的任务。**未完成** 汇总所有批次仍需处理的任务；**全部历史** 汇总所有批次已获取全文的记录。PDF 已保存但科研通采纳或对应消息尚未处理完成时，该任务会同时出现在“未完成”和已获取记录中。批量预检已经发现有效 PDF 的条目只计入跳过摘要，不创建新任务。

最近批次的范围、时间和摘要会随任务保存，重启后仍可查看；新一批操作替换当前批次视图，前一批没有完成的任务继续按原队列处理。旧版本没有批次记录时，从“未完成”或“全部历史”查找原有任务，再发起一次批量获取即可建立当前批次。

在 **下载设置 → 界面语言** 可选择简体中文、繁體中文或 English，切换立即保存并生效，不覆盖其他未保存的配置或账号输入。界面与插件的检查说明使用本地字典，论文标题、DOI、文件名和网站消息内容保持原文。任务标题和 DOI 可直接点击复制，成功后短暂显示“已复制”。

## 配置多个下载目录

设置集中在 **Zotero 设置 → 全文助手 → 下载设置 → 浏览器下载文件夹**。

- **首次发现**：尚无已保存目录配置时，尝试读取系统下载目录；同时从可访问的 Edge、Chrome 常用配置目录中读取下载路径设置。存在且可读取的路径会去重保存。插件只使用这些浏览器配置中的下载路径，不读取 Cookie 数据库、不获取密码，也不复制浏览器登录状态。
- **添加下载文件夹**：选择一个已有可访问目录，追加到列表，不替换其他目录。没有固定的用户名或磁盘路径；可添加自定义盘符和多个保存位置。
- **移除**：从配置中删除该目录，不删除目录或文件。已保存目录列表（包括主动清空的列表）后，重启不会自动重新发现并加回已移除目录。
- **自动检测下载目录**：仅在明确点击时重新发现并追加新路径，保留现有配置。修改了 Edge 或 Chrome 的下载位置后，可点击检测；配置文件不可读或使用其他浏览器时，手动添加即可。
- **子目录**：只检查列表中每个目录的直接文件，不递归遍历。浏览器保存到子目录时，应将那个子目录单独加入列表。

每次开始浏览器下载时使用当时的目录列表。添加、移除或检测导致列表实际改变时，插件会暂停正在等待下载的任务，并提示暂停数量；请在相应任务点击 **浏览器下载并自动入库**，按新配置重新开始。重复添加同一路径、移除不存在的路径或没有发现新目录时，列表不变，不会因此暂停。没有有效目录或目录不可读取时，会提示处理原因，不能视作监控已成功启动。

## 自动检查新增或变化的 PDF

每次显式启动时建立已有 PDF 的基线。与基线相比没有变化的旧文件不会被自动打开或导入；启动之后新增、重命名到该目录或大小/修改时间发生变化的 `.pdf` 文件才是候选。

候选文件的大小和修改时间需连续稳定至少 2 秒，并在读取后再次检查仍未变化。插件跳过浏览器临时下载扩展名，不把尚未完成的写入当作有效 PDF；随后验证文件格式和支持的大小范围（1 KiB 至 100 MiB），再核对论文身份。原始下载文件不会因入库而被删除。

没有活动下载任务时不持续检查这些目录。自动检查根据该任务的目录基线和论文身份处理文件，不按“最新 PDF”或相似文件名决定归属。较早下载且未变化的 PDF，可以在对应任务点击 **检查已下载文件** 或 **选择已下载的PDF**，两者的范围见下文。

## 已下载但没有入库

任务中的 **下载检查详情** 显示已检查 PDF 数、身份待核对数、不匹配数及最近检查时间。任务提示还会说明目录不可读、文件仍不完整、大小超限、文字提取失败或身份不符等原因。计数只描述当前检查过程，不代表目录里每个 PDF 都属于本篇论文。

1. 确认浏览器实际保存的位置已加入下载目录，且下载已经结束。插件不递归读取子目录，子目录应单独配置。
2. 对等待浏览器下载或已暂停的任务，点击 **检查已下载文件**。插件重新建立检查，并把当前目录中在该任务创建后创建或修改的 PDF 纳入重查；不会再次打开浏览器，也不会将所有旧文件直接入库。文件仍需稳定写入、格式有效且身份匹配。
3. 若出现候选文件，查看文件名和核验说明，再点击 **预览并核对**。插件重新读取并核对文件哈希和原文献身份，打开预览。确认标题、作者和 DOI 后，点击 **我已核对，是这篇论文** 才入库；从该候选入口进行的人工核对，即使复查已经判为匹配，也要求明确确认。
4. 对任务创建前的旧文件，或未出现在候选列表中的文件，使用 **选择已下载的PDF** 明确指定。

每个任务最多展示五个身份待核对候选。明确 DOI 不匹配的文件只显示拒绝原因，不提供“确认错篇”入口；多个等待任务同时匹配一个 PDF 时，也不会自动选择归属。候选文件在预览前或确认前发生变化，或者任务已暂停、切换或取消时，需重新检查，不能沿用旧确认。

诊断计数和普通浏览器候选列表保留在当前运行会话中；退出 Zotero 后不会继续扫描，也不恢复旧候选确认。任务、当前批次与已获取历史仍保留，重启后可用 **检查已下载文件** 重新建立检查。这个恢复方式不需要重新下载已经保存的 PDF。

## DOI、标题与人工确认

身份核验优先使用 PDF 首页可信的论文 DOI；明确不同的 DOI 视为不匹配，不会被相似标题放行。当前规则可识别部分明确的首页期刊与出版信息中的 DOI，以及结构明确的 DOI 换行。没有可用 DOI 时，可使用足够明确的完整标题建立匹配。引用文献中的 DOI、仅第二页命中、正文里提到的标题、无文本或提取失败等证据不足时，返回身份不确定。仅在首页较后位置找到目标标题时会提供具体说明，需预览后人工核对。

| 结果 | 自动检查目录 | 用户手动选择 PDF |
| --- | --- | --- |
| 明确匹配 | 只在唯一匹配一个等待任务时自动入库。 | 校验条目和权限后入库。 |
| 明确不匹配 | 不导入这个文件，继续等待对应论文。 | 拒绝导入并说明原因，不提供强行确认入口。 |
| 身份不确定 | 继续等待，在任务的检查详情中提供候选与原因；由用户选择预览核对，不自动入库。 | 显示 **待核对 PDF**，由用户预览并明确确认。 |
| 同时匹配多个任务 | 不自动选择条目，提示到正确任务手动选取。 | 在用户明确选择的任务中重新校验。 |

手动选择的未知文件会展示文件名、待关联文献和核验说明。点击 **预览待核对 PDF**，核对标题、作者和 DOI；确认确实是这篇论文后，点击 **我已核对，是这篇论文**。确认前会再次检查文件内容及原条目身份是否改变，防止确认了另一个文件。点击 **取消这次导入** 会清除待核对候选并保留任务，之后可重新选择文件或重新开始浏览器下载。

人工待核对状态不等于仍在监控目录。文件选择或候选核对会停止当前任务的目录检查；取消后可重新点击浏览器下载，或使用“检查已下载文件”重新开始。重新启动 Zotero 后需重新检查或选择普通浏览器下载的待核对文件，不能沿用旧的人工确认。科研通暂存待核对文件有单独的持久保存流程，不与这里的浏览器候选混同。

## 机构访问提示与本地经验

自动查找未取得 PDF，不等于本篇论文不能通过机构下载。页面提供明确的机构入口、只有“检查访问”迹象、普通登录提示、HTTP 访问限制或真人验证时，插件分别说明观察到的情况；个人账号登录本身不证明拥有全文订阅。Elsevier Linking Hub 明示同一文章编号的 ScienceDirect 文章地址时，插件可继续访问该地址，不猜测 PDF 下载路径。

普通浏览器成功与已有本地导入历史只作为成功获取的提示。对通过浏览器或本地 PDF 导入的已获取任务，只有你点击 **这是通过机构获取**，才记录你对本篇论文访问方式的明确确认；点 **撤销机构确认** 可移除这项声明。

经验按精确出版社主机和 DOI 保存来源与时间，最多保留 200 条。超过 180 天的确认只作旧经验；同站点其他论文的成功只提示可以尝试，不确认当前论文权限。记录不会获取浏览器 Cookie、密码或文件路径，不会把经验转换成登录凭据，也不会因此自动点击网站或消耗科研通积分。实际可访问性仍取决于当前机构订阅与网站会话。

## 等待、暂停和科研通兜底

单次目录检查最多 **30 分钟**。任务显示 **等待浏览器下载**，可随时点击 **暂停监控**。超时、停用插件或退出 Zotero 后停止检查，任务与历史保留；重启后不会后台自动恢复，可再次点击 **浏览器下载并自动入库**，也可用 **检查已下载文件** 重新检查已保存的文件。插件不检测普通浏览器窗口是否关闭，关掉浏览器不会自动结束目录检查，可在 Zotero 中暂停。

尚未取得全文且具备 DOI、没有已有求助记录的任务，在浏览器等待、待核对 PDF、暂停或失败后仍可明确选择 **科研通求助**。选择后先停止对应目录检查并清除待核对文件，再进入求助流程。已有求助使用 **查看已有求助**、**立即检查** 或 **下载到文库**，不会因换下载方式重复发布。

默认悬赏 **10 积分**，可配置 1–10000 的整数。输入时，单篇求助、批量求助、未发布任务重试及批量合计立即刷新；点击时先保存并捕获按钮显示的金额，再以同一金额调用求助。输入不合法或保存失败不会提交，其他尚未保存的设置不会被顺带覆盖。右键兜底捕获启动任务时最新已保存金额。已发布求助保持发布时金额，网站最低要求超过预算时暂停，不自动加价。

## 旧任务和验收边界

0.5.0 已移除专用 Edge 获取按钮。旧版尚未完成的专用 Edge 任务迁移为暂停，可选择当前默认浏览器下载或科研通兜底；旧版已获取记录仍保留原来的来源，不改写为新流程的成功结果。

旧版专用 Edge、PLOS、Nature、机构登录和科研通应助下载记录继续作为历史保留，详见 [0.5.0 验收记录](verification-v0.5.0.md) 与 [0.6.0 验收记录](verification-v0.6.0.md)。0.7.0 的最终结果集中在 [0.7.0 验收记录](verification-v0.7.0.md)，本说明不预填当前尚未完成的测试数或正式安装结论。合成 PDF、目录变化与 API 测试不能证明真实网站验证码已通过，也不能替代新求助发布、等待应助、下载和采纳的实站完整验收。
