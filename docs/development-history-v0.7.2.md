# 全文助手

在 Zotero 文库中批量选择文献，从条目网址、DOI 对应页面和开放获取来源取得 PDF，保存到原文献；仍未取得全文时，可按任务选择科研通兜底求助。只安装一个 Zotero 插件，不需要 Edge 扩展。

本说明对应 **0.7.2 私有预发布版本**，目标环境为 **Windows / Zotero 10.0.7**，安装清单兼容范围为 10.0.7–10.0.*。账号、设置、任务和消息集中在 **Zotero 设置 → 全文助手**。本版改进 PDF 首页文字与版面识别、DOI 和标题交叉核对、相关候选筛选及下载诊断，详见 [0.7.2 更新说明](release-v0.7.2.md)。仓库保持私有，采用草稿预发布流程；公共市场收录是独立步骤，当前未提交。下文旧版验收记录保留原版本归属，不表示已经在 0.7.2 重新执行。

0.5.0 移除专用 Edge 获取入口，改用 **浏览器下载并自动入库**：在日常默认浏览器中完成登录、验证并点击 PDF 下载，插件检查配置的下载文件夹，将明确匹配当前论文的新 PDF 添加到原条目。也可使用 **选择已下载的PDF**；文件身份不确定时，先预览，再明确确认。浏览器仍由用户操作，无需安装浏览器扩展。配置和核验细节见 [浏览器下载说明](browser-downloads.md)。

0.6.0 将界面整理为 **任务 / 下载设置 / 科研通账号 / 消息** 四个横向标签页，默认进入任务页。右键入口统一为 **全文助手** 子菜单，批量操作先检查每篇文献的本地 PDF，再显示本次加入、跳过和保留数量；全部已有 PDF 时不创建新的任务。切换标签页保留未保存的输入、任务筛选和勾选，不会触发求助或下载。

0.7.0 将 **进行中 / 需网页登录 / 待兜底 / 已获取** 限定为最近一次批量操作涉及的任务，**未完成** 与 **全部历史** 保留跨批次视图；最近批次和摘要会随任务保存，重启后仍可查看。新增简体中文、繁體中文和 English，点击标题或 DOI 复制，下载检查详情、重查已下载文件及候选 PDF 预览核对。机构访问经验只根据本机历史和用户明确声明提供提示，不把一次浏览器成功推断成整个出版社已授权。

0.7.1 将当前界面整理为 **任务 / 设置 / 科研通设置 / 消息**，积分和检查间隔数字居中显示。**自动接受网站最低悬赏积分** 默认关闭，保存并启用后可按网站已核实的最低要求提高本次悬赏。已经发起求助的任务也可检查已下载文件；本地文件入库后核验它与网站具体应助文件是否完全一致，再恢复科研通来源、采纳和对应消息已读。已获取历史显示已核实的实际积分，旧记录金额不明时明确标注待核实。

0.7.2 针对真实 PDF 中 `kākāpō` 与提取文字 `kakapo` 的字形差异，以及页脚 DOI 和页码、图标混在一起的版面问题，增加受限的首页版面文字补充识别。可靠 DOI 与标题互相冲突时不会自动入库。下载详情只推荐最相关的 **3 个候选**，并显示识别标题、DOI 和判定依据；明确不匹配、低相关与识别不足放在单独的折叠诊断中，同一文件反复检查不会累加成多个候选计数。

前一批仍在处理时，可以继续选择文献并加入下一批。所有批次共用一个先入先出的队列，后加入的任务接在已有等待项之后，旧失败任务重试也排到队尾；正在获取的任务继续运行。列表显示 **排队中 · 第 N 位** 和等待总数，队位指当前等待开始的次序，完成时间仍取决于网站响应。

文献标题中的常见斜体、加粗和上下标格式标签会转为纯文字显示，任务卡片及关联列表不再直接露出 `<i>` 等标签；数学比较和其他尖括号按安全文本保留，不执行来源 HTML，也不改写原文献元数据或 DOI 核验内容。

此前专用 Edge 验证循环的证据和普通 Edge 对照结果见 [历史排查记录](verification-troubleshooting.md)。这些历史记录不表示当前版本仍提供专用 Edge 获取按钮；当前下载流程不会读取浏览器 Cookie、接管日常标签页或自动点击验证码。

## 安装与批量获取

1. 获得本轮验收的安装包后，在 Zotero 插件管理器选择“从文件安装插件”，安装 `zotero-fulltext-assistant-0.7.2.xpi`。
2. 在文库选择一篇或多篇文献，右击 **全文助手 → 批量获取全文**。选择子附件时归到其父文献，同一父文献只处理一次；独立附件与笔记忽略。也可从该子菜单打开任务与设置。
3. 设置页默认进入 **任务**，筛选为 **未完成**。页首显示最近一次批量操作的数量摘要；有可用本地 PDF 的条目直接跳过。当前批次完成的任务可在 **已获取** 查看；以前批次的已获取记录在 **全部历史** 查看，均按完成时间倒序显示日期、来源和打开全文入口。没有可求助项时不显示批量求助栏。
4. 浏览器中可以下载时，点击任务里的 **浏览器下载并自动入库**。核对设置页中的下载文件夹，在默认浏览器自行下载并保存到其中任一目录，等待匹配后入库。
5. 对仍未取得全文的文献，勾选单项或“选择当前列表可求助项”，核对按钮所示每篇积分与合计，再点 **为所选文献发起科研通求助**。等待浏览器下载、待核对 PDF 和暂停状态仍保留符合条件的科研通兜底入口；已有求助使用 **查看已有求助**，不重复发布。也可使用右键 **全文助手 → 网页优先，科研通兜底（N 积分）**，按该次操作时的设置允许网页获取失败后进入求助流程，默认 N 为 10。

**设置** 包含界面语言、浏览器下载文件夹与机构登录保存状态；**科研通设置** 包含账号登录、余额与签到、悬赏积分、自动接受网站最低悬赏积分、检查间隔、自动下载与本地支出统计；**消息** 单独展示站内信与刷新入口。已有求助关联放在 **任务 → 关联已有求助**。标签页支持鼠标和左右方向键、Home、End；窄窗口可横向滚动标签栏。切换标签保留未保存的输入，新一批操作结束后会切回任务页展示摘要，后续轮询不强行改变当前标签页。最近一次批次的任务范围、时间和摘要持久保存，重启不会把它清空；下一次批量操作更新当前批次视图，之前尚未完成的任务仍留在总队列和“未完成”中。

| 筛选 | 范围与含义 |
| --- | --- |
| 进行中 | 当前批次中正在排队、获取、等待浏览器下载或处理已有求助的任务。 |
| 需网页登录 | 当前批次中提示登录、机构访问或人工验证的任务。该分类不是对订阅权限的确认。 |
| 待兜底 | 当前批次中尚未取得全文、可进一步手动处理或选择科研通求助的任务；自动查找未取得 PDF 不代表没有机构权限。 |
| 已获取 | 当前批次已保存 PDF 的任务。 |
| 未完成 | 所有批次尚未完成的任务，包括 PDF 已保存但采纳或对应消息操作仍未完成的任务。 |
| 全部历史 | 所有批次已获取全文的记录，按完成时间倒序显示。它不包含全部失败和等待记录。 |

分类计数根据任务范围计算；已经有 PDF 而在批量预检中跳过的文献仅计入摘要，不为显示本批数量而创建任务。由旧版本迁入且没有批次记录时，先从“未完成”或“全部历史”查看；下次批量获取后才有当前批次分类。新增批次不会重排正在执行的任务，也不清除旧任务。

在 **设置 → 界面语言** 选择简体中文、繁體中文或 English 后立即保存生效，重启后保留。切换语言不保存或覆盖其他尚未提交的积分、间隔、账号或链接输入。插件按钮、状态、核验提示与错误说明使用本地字典；论文标题、DOI、文件名和网站原消息内容保持原文，不联网翻译。在任务卡片点击标题或 DOI 可复制对应纯文字，旁边短暂显示“已复制”；不会修改 Zotero 元数据。

批量预检遍历文献的本地附件，包括存储附件和链接文件。文件必须存在、可读、为普通文件，具有 PDF 开头和结尾标记，并在检查期间保持大小与修改时间稳定；只有网页链接、丢失文件、HTML 伪装或不完整文件不算已有 PDF。该检查读取文件头尾，不完整解析内容，也不重新核对论文 DOI。已有任务、已获取历史与求助关联不会因跳过而清空。可重试且没有求助关联的失败或暂停任务复用原任务重新排队；普通批量不会沿用旧的未提交求助许可。已获取记录的本地 PDF 丢失时复用任务修复，已有远端求助及原积分保留。

普通“批量获取全文”不会为新任务自动开启科研通求助。选用科研通兜底时会查询 DOI 元数据、检查最低积分与余额、查找自己的已有求助，再按任务预算规则发布。默认不加价；只有已保存并启用 **自动接受网站最低悬赏积分** 时，网站最低要求高于设置值才采用已核实的最低值。余额不足、结构变化、最低积分无效或提交结果不确定时停止并说明原因，不重复发布。

任务和已获取历史保存在本机，关闭或重启 Zotero 不会清空。列表随任务进度自动更新，无需为了查看新状态重新打开设置；切换筛选会清除勾选，避免把隐藏项一起提交。关闭 Zotero 后不轮询，下次启动继续读取原有记录。旧版已获取任务使用原更新时间补齐完成日期，之后启动不会把历史完成日期改成当天。

## 网页全文与机构访问

获取模块读取 PDF 元数据和下载入口，必要时通过 Zotero 隐藏浏览器渲染，再尝试 Zotero 的开放获取来源。下载内容通过 PDF 格式与大小检查后才导入。任务可暂停、重试，附件始终关联原条目。

出版社页面的机构入口、可能的登录提示、访问限制、真人验证和自动查找未找到会分别记录。一般个人账号“Sign in”不直接算作机构访问；明确的机构入口也只是可尝试的路径。Elsevier Linking Hub 页面明示了同一文章 PII 的 ScienceDirect 地址时，插件可继续读取该文章页，不凭空拼接 PDF 下载地址。

没有关联科研通求助的任务通过浏览器下载或本地 PDF 导入成功后，只记为本机的浏览器获取经验。若你确实通过机构取得这篇论文，可在已获取任务上点击 **这是通过机构获取**；需要更正时使用 **撤销机构确认**。已经关联求助的任务不会仅凭本地文件入库生成出版社访问经验。只有明确的机构确认操作才形成机构确认记录，按出版社主机和 DOI 区分，超过 180 天降为旧经验。其他论文在同一站点成功只作为提示，不代表当前论文也在订阅范围；即使是同篇历史确认，也不保证网站当前会话或订阅仍有效。该经验记录不保存浏览器 Cookie、账号或下载文件路径，也不会自动替你登录或发起求助。

任务中的 **打开网页** 使用全文助手的 **出版社与机构登录专用窗口**。常规跨域跳转和弹出页面保留在插件内部；完成登录后，点击右上方 **完成登录并重试此文献**，重新获取当前文献。已有附件的任务显示“打开全文”。科研通另有独立的登录窗口与会话。

专用窗口默认勾选 **记住此窗口的机构登录（加密）**。只有用户保持该勾选并点击 **完成登录并重试此文献**，才会把本窗口经过的出版社、机构登录站点加入记住范围。授权范围内的会话备份加密保存在本机 Zotero 登录管理器中，用于后续文献和重启后恢复；仅打开窗口不会新增站点授权。设置页用一行显示保存状态和时间。网站仍决定登录有效期，过期后需要重新登录。

插件不读取或复制 Edge Cookie。Edge 中能下载，不等于插件已有相同机构登录状态。此前已验证在专用窗口完成 CSTCloud 机构登录后，Nature `10.1038/nn.4346` 能取得全文并导入原文献，重复获取不新增附件。0.3.0 的本机会话存储机制已使用合成测试 Cookie 完成真实 Zotero 跨进程验收；这不等于已经验证 CSTCloud 等真实机构网站在重启后仍认可登录，服务端有效期仍由网站决定。

**浏览器下载并自动入库** 使用 Windows 当前默认浏览器及其自己的登录状态；默认浏览器为日常 Edge 时，就在日常 Edge 中打开。插件会停止该任务的旧获取流程并等待清理，然后开始检查配置目录、打开论文页面。用户自行完成验证并点击网站下载按钮，插件不控制浏览器页面，也不要求开放调试端口。

首次建立目录配置时，插件尝试发现系统下载目录，以及可读取的 Edge / Chrome 常用配置中的下载位置。支持保留多个目录；可通过 **添加下载文件夹** 追加、通过 **移除** 删除，或显式点击 **自动检测下载目录** 追加新发现的位置。移除只修改配置，不删除文件；已保存配置（包括空列表）后，重启不会自动把已移除目录加回来。目录列表实际改变时，正在等待下载的任务会暂停，提示暂停数量；请点击相应任务的浏览器下载按钮按新目录重新开始。重复添加同一路径或检测无新结果时不会暂停。自动发现失败时可手工添加，没有写死任何用户的磁盘路径。

每次点击浏览器下载后最多检查 **30 分钟**。仅检查所列目录的直接文件，不递归扫描子目录；需要子目录时单独添加。启动时记录已有 PDF 的大小和修改时间，只读取之后新增或发生变化、且大小和修改时间已稳定的 PDF，再校验文件格式和论文身份。身份核验交叉检查首页可信 DOI 和完整标题；可用的可靠单项证据仍能建立匹配，两项证据冲突则转入人工核对，不靠文件名或“最新下载”猜测。

自动检查只导入明确匹配且能唯一对应等待任务的文件。可靠证据表明属于另一篇论文时拒绝导入；身份不确定但存在相关线索时，任务继续等待，并在 **下载检查详情 → 推荐核对** 中按相关程度展示最多 **3 个候选**。每项列出文件名、识别标题、DOI 和判定依据；标题相似度只辅助筛选，不是匹配概率。点击 **预览并核对**，核对文章后再明确确认入库，不自动把未知文件归给某篇文献。多个任务都匹配同一文件时，保留提示，要求在正确任务中手工选取。

PDF 已下载却没有入库时，查看 **下载检查详情** 中的已检查数、相关候选数、已排除数、识别不足数和最近检查时间。**已排除与识别不足** 默认折叠，区分明确不匹配、可靠标题低相关与提取证据不足，并展示最多 5 条诊断记录；识别不足不代表文件错误。当前检查按文件路径保留最新分类，重复检查或同一路径的文件被替换后更新结果，不重复累加。点击 **检查已下载文件** 可重新检查配置目录中在该任务创建后创建或修改的 PDF，重新开始等待，但不会再次打开浏览器；任务创建前的旧文件或未被推荐的文件仍可用 **选择已下载的PDF**。重查与候选文件仍执行格式、身份和内容变化核对，不按文件名猜测。

已经关联科研通求助的未完成任务同样提供 **检查已下载文件**。目录检查期间保留原求助关联，暂停该任务的远端应助轮询；点击 **立即检查** 可切回远端检查。明确匹配的本地 PDF 入库后，会继续核对它与网站具体应助文件的内容；只有核验成功才记为科研通来源并完成采纳、对应通知已读。不能核验时保留本地全文和原求助，可在历史中再次点击 **核验科研通文件**，不会另发一条求助。

任务显示“等待浏览器下载”，成功后记录为已获取，来源为“浏览器下载”，可从当前批次的“已获取”或跨批次的“全部历史”查看。点击 **暂停监控**、超时、停用插件或退出 Zotero 后停止检查，任务记录保留；重启后可点击浏览器下载重新打开论文，或使用 **检查已下载文件** 重新检查已保存的 PDF。下载诊断计数与普通浏览器候选列表属于当前运行会话，重启后通过重查重新建立。关闭普通浏览器窗口不会被插件检测到，目录检查仍会运行到暂停或超时。迁移后的旧专用 Edge 未完成任务会暂停，继续使用当前浏览器下载或科研通入口。

本地导入要求任务已经关联文献，且文库允许保存附件。手选 PDF 也执行格式、DOI/标题核验；明确不匹配时拒绝导入，身份不确定时显示“待核对 PDF”，提供文件名、待关联文献和核验说明。请点击 **预览待核对 PDF**，核对后点击 **我已核对，是这篇论文**；取消则保留任务，可重新选取文件。确认时再次核对文件和条目未改变。已有有效 PDF 会复用，避免重复附件；手选导入成功后来源为“本地 PDF”。从监控中转入文件选择会停止监控，取消选择后可再次点击浏览器下载恢复。

对已有科研通求助的任务，**选择已下载的PDF** 即使自动识别匹配，也先要求预览并明确确认。确认只适用于这次选择的具体文件；文件或原文献在此期间改变时停止导入。之后的来源核验还要求网站文件与已保存附件完全一致，人工确认不能覆盖明确的错篇证据。没有对应网站文件或文件内容不同，来源继续保留为本地 PDF。

## 科研通账号、求助与等待

- 首次使用时，请在当前 Zotero 的账号区填写账号密码，点 **保存并打开登录**；插件填写真实登录页，用户完成验证码并点击网页登录。也可直接选择“网页登录”。登录成功后显示当前绑定的站点显示名。
- 账号密码与会话备份保存在本机 Zotero 登录管理器；科研通会话独立于 Edge。已验证登录后退出并重启 Zotero 能够恢复登录；**会话有效期仍由科研通控制**，过期或被网站撤销后需重新登录。退出账号会清除该会话，保留保存的账号密码供下次登录。
- 默认每篇悬赏 **10 积分**，可配置 1–10000 的整数。输入时，单篇、批量求助和未发布任务的重试按钮立即显示当前基础金额，批量合计同步更新，无需先退出输入框。点击后先保存该次按钮显示的积分；非法金额或保存失败不会发起求助。右键兜底按启动该批任务时的最新已保存设置捕获金额。
- **自动接受网站最低悬赏积分** 默认关闭，必须点击 **保存设置** 后生效。关闭时，最低要求高于基础积分则停止；开启时使用基础积分与网站已核实最低要求中的较高值，并按这个实际值校验余额和提交。例如基础积分 10、网站最低 30，开启后该任务以 30 积分发布，显示“10 积分起”及可能上调的提示。基础积分和此开关都在任务获准求助时保存快照，之后修改全局设置不会改变已经排队任务的授权；已发布求助始终保持原悬赏。提交结果不确定时只核实原请求，不因重试开关变化再发布。
- 科研通来源旁显示网站已核实的金额：采纳完成后为 **已支出 N 积分**，尚未采纳为 **悬赏 N 积分（待采纳）**。旧任务若只有曾经的默认积分、无法核实网站实际悬赏，则显示 **积分待核实**；不会用当前默认值推算历史支出。检查求助或核验文件时获得可靠金额后，记录随任务持久保存。
- **科研通设置** 中提供支出统计，汇总本机任务历史中已经采纳且金额已核实的积分总额、计入条数和平均每条积分，并列出最近 10 条支出明细。尚未采纳或金额不明的记录不计入这些金额与平均值；核实后再更新。统计根据持久保存的任务与采纳凭据生成，可跨重启查看，范围仅为插件保存的本地历史，不代表科研通账号的完整账单或当前余额。
- **科研通设置** 中提供每日签到提醒与核实，默认启用。Zotero 运行且科研通会话可用时，在本机时间每天 **06:00** 后只读检查当天签到状态；打开全文助手时补查。关闭 Zotero 后不会运行定时检查，下次启动或打开助手时再按条件补查。
- 签到需要本人点击官方网站的按钮。插件在 **余额与签到** 区提供 **去网页签到** 入口，随后短时只读复查结果，并展示网站确认的签到状态、积分余额与可核实奖励；不会发送自动签到请求、代点按钮或绕过验证。已确认签到时按钮显示 **查看签到页面**，也可点 **刷新余额与签到** 手动核实。当天未核实的奖励不显示为已获得，跨日会清除昨天的已签到及奖励标记；旧余额仅作为上次查询结果。
- 签到查询按账号保存在本机，退出或切换账号不显示上一账号的余额。普通补查至少间隔 2 分钟，错误后至少间隔 15 分钟再自动尝试，避免重复请求；关闭提醒可停止自动检查，仍可手动打开官网。
- “等待时检查间隔”可设为 **60–3600 秒**，默认 **60 秒**；等待任务检查和已登录账号的消息自动刷新使用当前保存的设置。任务状态变化会直接更新设置页。关闭 Zotero 后不在后台轮询，下次启动按保存的任务状态继续。
- 检查已有求助时遇到可重试的临时网络错误，会提示等待时长并逐步延长重试间隔，最长 1 小时；登录失效或提交结果不明确时，不按网络错误自动重发求助。
- 默认自动下载已应助文件；核对论文身份并保存到原文献后，采纳这份文件、结算该求助的原悬赏，再将对应上传通知标记已读。关闭自动下载后，可对“文件可下载”的已关联任务点击 **下载到文库**。下载前核对求助 DOI、账号归属及文件权限，身份不确定时等待用户核对。
- 下载优先使用**当前账号已核实的免积分高速权益**，否则使用普通免费线路；不会仅凭旧积分记录推定权限，也不会自动购买高速下载。下载中和已获取历史会在来源旁显示本次实际使用的 **免积分高速** 或 **普通线路**。旧记录没有线路信息时不作推测。
- 文件传输遇到可重试的超时或临时网络错误时，会重新获取下载地址：可用时尝试已核实的免费备用高速线路或另一个普通节点；仍失败则按任务退避策略等待重试，最长间隔 1 小时。每次重新获取线路都核对当前权限，不自动改用收费线路。登录失效、权限不明、PDF 校验失败等问题需按任务提示处理。
- “关联已有求助”默认 **只跟踪，不关联文献**。这会创建可读取应助状态的跟踪任务，但没有附件要保存到的 Zotero 父条目；因此即使网站文件已就绪，也不会自动入库。界面会显示 **待关联文献**，而非让用户误以为正在下载。
- 对这类任务点击 **关联文献**，从 DOI 相同、可写入附件的文库条目中明确选择，再点 **确认关联**。下拉框默认空选，不会猜测或采用批量最后一篇文献。没有候选时，先在文库添加对应文献并补全 DOI。关联时会重新核对远程求助和所选条目；开启自动下载时继续获取，关闭时使用 **下载到文库**。也可在最初添加求助链接时，明确选择已有任务作为关联文献。
- 同一求助不能同时关联两篇文献，也不能覆盖文献已有关联。遇到重复条目时，使用已有附件或在文库合并重复项；正在处理的任务应先暂停，再关联已有求助。
- 消息标题不再显示含义不明的数字，最近刷新时间放在右侧 **刷新消息** 按钮旁。读取列表本身不修改未读状态；已完成采纳的文件只处理能够精确对应到它的上传通知，其他文件、提醒和普通站内信保持原状态，没有全站一键已读。点击具体消息会打开网站页面。已上传文件可能因过期、撤回或网站权限限制而无法下载，任务会显示原因。
- 提交结果不确定时显示“提交待核实”。先检查网站上的已有求助，再使用“立即检查”，避免再次发布同一请求。
- 文献信息查询返回的 DOI 与条目不一致时，会区分条目 DOI 和网站返回值；发生在发布前的校验失败不会创建求助，不能仅凭标题相似继续。已经收到新求助编号、但详情核验失败时，单独保留 **已发布求助待核对** 记录，提供 **打开已发布求助核对**。这里的编号尚未绑定文献；**立即检查** 只重读这一条求助，核对账号与当前 Zotero 条目 DOI，匹配后再绑定，不自动改写条目或重复发布。
- 历史求助已关闭或文件已过期时，打开网站处理，插件不会自动重新发布。退出或切换科研通账号会暂停相关求助任务，确认账号后再重试。

任务及当前批次记录位于 Zotero 数据目录的 `fulltext-assistant/tasks.json`，防重复提交记录位于同目录 `submission-intents.json`，机构访问经验位于 `access-history.json`，按账号区分的签到查询结果位于 `checkin-status.json`，其中不保存账号密码。插件不会预置示例任务或上传整个文库。暂停只停止本地处理，不撤销网站已有求助。

### 应助文件核验、采纳与消息

自动流程依次为 **核对 DOI 或明确的完整标题 → 保存 PDF → 采纳具体应助文件 → 标记对应上传通知已读**。采纳会结算这个求助的原悬赏，不是再次发布求助。明确错篇的文件不入库、不采纳；无法自动确认身份时，任务显示 **待核对 PDF**。请先 **预览待核对 PDF**，确认是所需论文后再点击 **我已核对，是这篇论文**，随后继续入库、采纳与已读。

PDF 已入库而网站操作尚未完成时，任务仍保留全文，并显示 **已获取 · 待采纳**、**已获取 · 采纳待核实** 或 **已采纳 · 待已读**。可点击 **重试采纳与已读**；采纳响应不确定时使用 **核实采纳状态**，只读取网站状态，不重复提交采纳。网站尚未确认时继续保留提示，可打开 **查看已有求助** 人工核对。采纳与已读失败会独立记录并重试，不重新下载或重复添加附件。

待核对的科研通 PDF 和已入库文件的核验记录会保存在本机，重启后可继续核对或完成剩余步骤。每次继续都会核对原账号、求助、具体文件与现有附件；文件内容或关联变化时停止自动采纳。退出 Zotero 后不会继续联网处理。

已获取且有关联求助的历史若没有具体文件的核验记录，会显示 **核验科研通文件**，包括此前来源显示为本地 PDF 或浏览器下载的记录。点击后重新核对网站应助文件：只有论文身份匹配，且它与已保存 PDF 的 SHA-256 完全一致，才将来源记为科研通并补做采纳和对应消息已读；保留原附件和完成时间，不重复入库。不会仅凭标题、文件名或同一个求助编号猜测应当采纳哪份文件。文件已过期、内容不同或身份不明时，保留原附件和来源并提示到网站处理。

本次明确人工确认的本地 PDF 若属于扫描件、无法自动提取论文身份，只在随后核验到完全相同的网站文件时，才可使用这次确认继续采纳。该授权绑定本次附件、内容指纹和原文献，不泛化为其他文件，也不为旧记录虚构人工确认。退出账号、修改附件或改变文献关联会阻止迟到的核验继续采纳。

## 开发与检查

需要 Node.js 24 和 Python 3.10 或更高版本。Python 构建只使用标准库，npm 依赖仅用于测试，不打包进 XPI。

```sh
npm ci --ignore-scripts
npm test
python build.py --output dist
```

`python build.py` 不带参数时输出到开发工作区的 `outputs`；`--output` 的相对路径以当前目录为基准。构建生成 XPI、源码 ZIP，并打印 XPI 的 SHA-256，排除开发依赖、本地账号/任务数据及构建输出。

历史 0.3.0 本地完整测试集 **164/164 通过，设置页 DOM 回归通过**；该版实际 XPI 原生验收 **25/25 通过**，包含机构窗口 9 项检查。设置页回归覆盖默认未完成与完成历史、显式关联及陈旧状态、手动/本地导入、线路显示、机构登录保存摘要、消息刷新位置和安全文本。此前 0.2.1 的测试数量为 126 项，其中应用层 49 项、科研通适配 35 项，该旧版数量不作为 0.3.0 的分项统计。GitHub Actions 会对推送版本执行同套测试与构建，具体结果见仓库 Actions。模拟测试用于检查错误和边界路径，不能替代实站结果。

GitHub Actions 在主分支更新和 PR 时测试、构建并保存产物。推送与清单版本一致的 `v*` 标签会生成预发布草稿。构建和社区收录细节见 [发布说明](PUBLISHING.md)。
