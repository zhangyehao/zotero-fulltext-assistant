# 构建、私有发布与社区收录

仓库：`zhangyehao/zotero-fulltext-assistant`，当前版本为 **0.6.0 私有预发布版本**。仓库保持 **private**，通过 **draft prerelease** 准备安装包，未提交社区市场收录。本轮构建、正式安装和验证范围见 [0.6.0 验收记录](verification-v0.6.0.md)；远端同步、标签和草稿状态以对应仓库记录为准。发布草稿、公开发行和市场收录是不同步骤。

0.5.0 移除专用 Edge 获取入口，提供普通默认浏览器下载与多个配置目录的 PDF 检查。首次建立配置时尝试发现系统、Edge 和 Chrome 的下载目录；以后仅在用户点击检测时追加发现结果。浏览器中的验证和下载按钮仍由用户操作。只读取本次开始检查后新增或修改且稳定的 PDF，明确匹配 DOI/标题时自动入库；自动发现的未知文件不会被猜测关联，手选未知 PDF 必须预览并明确确认，明确不匹配文件拒绝导入。流程及范围见 [浏览器下载说明](browser-downloads.md)。

0.6.0 增加横向 **任务 / 下载设置 / 科研通账号 / 消息** 标签页，右键入口合并为 **全文助手** 子菜单。批量加入前遍历本地附件，跳过具备 PDF 头尾标记且读取期间稳定的本地 PDF；保留旧任务、历史与远端求助关联，并显示本次加入、跳过、保留及异常数量。切换标签页保留输入与选择，新批次结束时展示任务摘要；轮询不改变当前页面，没有可求助项时隐藏批量求助栏。

连续添加的批次共用先入先出的队列，新增任务和重新排队的旧任务放在队尾，已有获取继续运行；任务显示当前等待队位。科研通应助文件先核对论文身份，再入库、采纳具体文件并结算原悬赏，最后只标记这份文件对应的上传通知已读。身份不明时先预览确认；没有全站一键已读。

待核对文件和采纳核验记录会跨重启保留。PDF 已入库后，采纳或已读失败独立重试；采纳响应不确定时只核对网站状态，不盲目再次提交。旧历史可点击 **核验并补采纳**，只有论文身份匹配且网站文件与本地 PDF 的 SHA-256 完全一致才继续；不根据文件名或求助编号猜测。具体操作见 [README](../README.md#应助文件核验采纳与消息)。

标题显示将 Zotero 常见行内格式标签转成纯文字，覆盖任务卡片和关联文献列表；数学尖括号及其他文本不被泛化删除，不使用来源 `innerHTML`，原元数据和 DOI 核验保持不变。

本轮测试与安装状态以 [0.6.0 验收记录](verification-v0.6.0.md) 为准，不能用旧版数量或安装结论替代。采纳和单消息已读的 POST 使用受控模拟，没有真实采纳、发布新求助或消费积分；保存的官网页面只用于只读核对协议。积分输入即时更新按钮与合计，执行时先保存并捕获显示金额，已发布求助保持原价，浏览器未完成状态仍可明确选择科研通兜底。

下文 0.5.0、0.4.1、0.3.0 与 0.2.x 保留其历史版本归属，不作为 0.6.0 重新验证或当前安装状态。实站验证说明另见 [README](../README.md#已完成的实站验证)；构建或创建 Release 不会扩大实际验证范围。收录机制于 **2026-11-04** 根据下方项目仓库 README 与源文件核对，提交前应再次检查其贡献要求。

## 当前私有开发流程

1. 更新并核对 `manifest.json`、`package.json` 和锁文件中的版本；稳定保留插件 ID，不要为每次版本变更 ID。
2. 本地运行 `npm ci --ignore-scripts`、`npm test`、`python build.py --output dist`。构建会输出 XPI、源码包与 SHA-256。
3. 把审查过的修改推送至 `main`，查看 **CI** 工作流。该工作流只生成 Actions 构建产物，不创建 GitHub Release。
4. 需要发布候选版本时，在已验证的提交创建 `v<manifest version>` 标签并推送。**Prepare release draft** 会再次测试和构建，创建带 XPI 与源码包的 **draft prerelease**。
5. 在 GitHub Release 草稿检查附件和说明，写清真实验证范围及当前限制，再决定是否发布。仓库保持私有时，已发布的 Release 仍只对有仓库访问权的人可用。

当前候选版本的标签名示例如下，仅在相同版本的测试和安装包验收完成后使用；先检查远端是否已有同名标签，不重复创建或覆盖旧标签：

```sh
git tag v0.6.0
git push origin v0.6.0
```

标签工作流会拒绝标签、清单和 package 版本不一致的构建。工作流不更改仓库可见性、不提交外部收录、不部署更新源。重复使用已存在的 Release 标签会由 GitHub CLI 拒绝创建，应检查原草稿，避免覆盖已审查的发布内容。

仓库当前没有配置公众可用的自动更新源。私有仓库的 Release 和 raw 文件需要授权；普通 Zotero 安装不能凭一个私有 GitHub URL 匿名获得它们，第三方市场的公共采集器也不能读取此仓库。不要在 XPI 或更新 URL 中存放个人访问令牌。继续私有测试时，向有访问权的协作者提供 XPI，使用手动安装更新。

## 0.6.0 发布前核对

- 交付 XPI、源码包、清单版本和验收报告必须均为 0.6.0；报告缺失、版本不一致或包含失败项时明确标记，不继承旧包的通过状态。正式安装另行确认，安装前后核对任务标识、完成附件关联、下载目录与登录状态。
- 检查四个横向标签页的默认状态、鼠标和键盘切换、窄窗口布局，以及切页和批量摘要到达时未保存输入、任务筛选与勾选仍保留。全完成、空列表或没有可求助项时隐藏批量求助栏，完成历史仍可查看。
- 检查 **全文助手 → 批量获取全文** 子菜单唯一且可用、附件归父与去重、本地存储/链接 PDF 预检、首个附件丢失或无效但后续有效、链接 URL 不算本地 PDF，以及所有项目已有 PDF 时不创建任务。已获取但文件丢失时复用原任务修复；旧求助及原预算、进行中的任务和受保护提交不被覆盖，普通重试不继承旧求助许可。
- 检查新一批操作的数量摘要和逐项失败继续处理，同一摘要在轮询时不打断当前页面；本次摘要不持久化，不把摘要消失误写为任务历史丢失。
- 检查前批运行中追加下一批、旧任务重试与缺失附件修复均进入队尾，已有等待顺序不被改写；队位显示应对应当前等待项，重复加入活动任务不创建副本。
- 检查应助文件的错篇拒绝、未知身份预览确认、保存后才采纳、原悬赏结算说明，以及只对精确文件的上传通知单条标记已读。账号、请求、文件或附件发生变化时停止；采纳响应不明只读取状态，已获取 PDF 不因收尾失败重下或重复入库。
- 检查待核对文件与核验记录跨重启恢复、采纳/已读独立重试、已采纳文件幂等处理及连续分页消息核对；旧历史补采纳须比较论文身份和完整文件哈希，缺少可靠关联时保留人工处理入口。
- 检查多目录的首次发现、显式检测、增删保存、重启不重新加回已移除目录、非递归扫描与旧 PDF 基线；目录列表实际改变时暂停等待任务并提示数量，无变化不暂停；默认等待上限为 30 分钟，退出后停止，重启需手工重新开始。
- 检查同一文件下载过程中暂不读取、稳定后复核、DOI/标题匹配和冲突、自动未知文件被忽略、多任务同时匹配时不随意选择条目，以及手选未知 PDF 预览/确认/取消和确认前文件变化。
- 检查设置输入后的单篇/批量积分与合计即时更新、保存失败不提交、提交金额与按钮一致、已发布求助不被改价，以及浏览器各未完成状态仍保留可用的科研通入口。
- 默认浏览器打开与文件夹检查不构成真实网站下载验收；合成 PDF、被替换的系统启动边界和本地夹具应在报告中注明，不表示真实 CAPTCHA 或机构认证已通过。不得把历史真实 PLOS / Nature 下载写成本轮重新实测。
- 采纳和标记已读的受控 POST 模拟应明确标注；未经实测，不宣称真实服务器已完成悬赏结算或消息修改，也不把私有草稿描述为已公开发行或已被市场收录。

## 历史：0.3.0 使用变化与验收范围

本节记录 0.3.0 当时的功能、测试及安装结果；其中的测试数量、下载时间和安装版本不代表 0.6.0 的当前状态。

- 任务默认筛选 **未完成**；完成后移入 **已获取**，按完成日期显示来源，保留“全部历史”。任务仍保存在原来的本机任务文件中，重启不清空，也不重写历史完成日期。列表自动跟随任务更新；切换筛选清除勾选。等待任务和已登录账号消息使用保存的检查间隔，当前代码范围 60–3600 秒、默认 60 秒；关闭 Zotero 后不轮询。
- 只输入已有求助链接而选择“只跟踪”时，没有 Zotero 父条目，文件已就绪也不能自动入库。该任务显示 **待关联文献**；用户点击 **关联文献**，明确选中 DOI 相同且允许写入附件的条目，再 **确认关联**。不自动选择候选，关联时重新检查 DOI、权限和冲突；之后遵守自动下载设置。已有 PDF 可复用。
- 科研通下载按当前账号已核实的免积分高速权益优先选择，否则使用普通免费线路，不自动购买。下载与完成历史显示实际线路；旧记录无线路信息时不猜测。临时传输失败会重新取下载地址，可用时尝试已核实的免费备用线路或普通备用节点，继续失败则退避重试，最长 1 小时。每次重新取得线路仍须检查当前权限。
- 专用机构窗口默认勾选“记住此窗口的机构登录（加密）”，但仅在用户保留勾选并点击 **完成登录并重试此文献** 时，才把本窗口经过的相关站点加入记住范围；仅打开窗口不新增授权。授权会话在本机 Zotero 登录管理器加密保存，设置页只显示简短保存状态与时间，不列内部站点数据。网站决定会话有效期，不能承诺永久登录。
- Cloudflare 等真人验证可能与 Zotero 内嵌浏览器不兼容。插件识别后提示人工处理并暂缓同站点重复请求，不自动操作验证码或保证验证通过。用户可用系统浏览器正常登录、下载 PDF，再通过已关联任务的 **选择已下载的PDF** 导入原文献；专用窗口也提供导入入口。文件格式校验不等于核对论文内容，用户需选对文件。
- 消息标题移除数字计数，最近刷新时间放在右侧刷新按钮旁；所有任务、设置和账号操作仍在 Zotero 原生设置页完成。

0.3.0 完整测试集 164/164 与设置页 DOM 回归均已通过；实际 XPI 原生验收 25/25 通过，包含机构窗口 9 项检查，正式文库当时已原位安装 0.3.0。该版本验证时已核实账号的免积分高速权益，并经高速 VIP 线路取得 551074 字节有效 PDF，文件传输 459 毫秒、完整检查与下载 1163 毫秒；没有发布新求助或购买权益。该时间只是一次样例测量。

0.3.0 的正式文库验证中，也已通过原生设置页，将已有未关联求助明确关联到选定文献，然后经免积分高速自动入库，保存完成日期与线路；任务从未完成移入已获取历史，当次数量分别为 4 → 3 和 4 → 5。

机构会话的本机存储机制已使用合成测试 Cookie、真实 Zotero 登录管理器和真正退出/重开的不同进程完成验收，准备阶段 11 项、恢复阶段 16 项均通过。恢复值与 secure/httpOnly/sameSite/expiry、默认上下文保持正确，不延长原会话有效期、不覆盖较新 Cookie，并排除未授权站点和其他上下文；测试后清理通过。该结果证明本机存储与恢复机制，不可表述为真实 CSTCloud 授权已跨重启通过。

本地 PDF 导入也已使用最终 0.3.0 XPI 和原生文件选择器完成 9 项检查。通过界面选择已有的 551074 字节 PDF 后，来源、正确父条目、文库、存储文件、PDF 有效性和完成日期均通过；第二次导入复用已有附件，没有新增 PDF 或改变完成日期，也没有发起新求助。此测试包含人工选择文件，耗时不作为网络下载速度引用。

真实机构服务端在重启后是否继续认可登录、免费备用线路的真实故障切换尚未实测；备用线路和重试的错误路径已由单元测试覆盖。下文 0.2.x 的实站和安装包记录继续保留原版本归属，不把旧版下载结果写成 0.3.0 全部复测通过。

## 进入公众发行前需要完成的工作

公众发行说明应保留这些具体范围，明确 **真实新求助的最终创建 POST 未执行**，发布后等待新应助的完整链路尚待验收。出版社与机构登录专用窗口让常规跨域与弹出页保留内部，并提供“完成登录并重试此文献”；CSTCloud/Nature 这一例端到端已验证，其他机构与出版社仍需分别验证。

当前 0.6.0 发布说明应引用本轮日志和版本一致的安装包验收报告，正式安装状态单独核实。历史 0.5.0 的 341 项、0.4.1 的 246 项、0.3.0 的 164 项和 0.2.1 的 126 项测试（应用层 49 项、科研通适配 35 项）不可沿用作当前版本测试数量。GitHub Actions 会对推送版本执行同套测试与构建，具体结果见仓库 Actions。发布说明还应保留默认 10 积分可调、操作时捕获显示金额、未取得全文时明确选择科研通、临时网络错误退避重试、单一求助不能绑定两篇文献等行为说明。新增支持范围和兼容版本应另行验证；测试夹具通过不能代替真实网站结果。

准备公众发行时，再明确选择把本仓库公开，或建立只分发安装包的公共仓库/网站。当前文档不会自动执行任何公开操作。公开下载地址必须能匿名取得 XPI，版本与安装包内清单一致；提供 README、许可证、兼容范围、问题反馈入口和清晰的限制说明。

Zotero 自身的自动更新与第三方市场收录是两项独立工作。公开后如需自动更新，应按照 [Zotero 官方插件开发文档](https://www.zotero.org/support/dev/zotero_7_for_developers) 配置有效的 `update_url` 与更新清单，保持原插件 ID，并实际验证旧版升级到新版。当前 `.invalid` 占位地址不能用于自动更新。

## syt2 的 Zotero Addons 市场

[syt2/zotero-addons](https://github.com/syt2/zotero-addons) 是第三方插件市场客户端。其 **addon-scraper** 数据源来自 [syt2/zotero-addons-scraper](https://github.com/syt2/zotero-addons-scraper)，新插件条目应在后者贡献，而不是直接修改市场客户端。

当前贡献机制为：fork scraper 仓库，在 `addons` 目录新增以 `{owner}@{repo}` 命名的文件，再提交 PR。此插件未来对应文件名为：

```text
addons/zhangyehao@zotero-fulltext-assistant
```

文件可为空；如需分类，可写最多两个有效标签。本插件可考虑：

```json
{"tags": ["attachment", "integration"]}
```

这不是插件完整元数据文件；名称、描述、版本和兼容范围由采集器从仓库发行版与 XPI 中读取。不要根据旧示例自行填入未验证的 `repo`、`desc`、`mirrors` 字段。

合并后，scraper 的工作流采集发行版并向 `publish` 分支及其最新 Release 输出插件索引。市场显示还取决于采集成功、有效 XPI、兼容范围及客户端选用的数据源。只有私有仓库或仅有未发布草稿时，不应宣称已经可以被公众市场安装。

参考：[scraper README](https://github.com/syt2/zotero-addons-scraper/blob/master/README.md)、[addons 目录](https://github.com/syt2/zotero-addons-scraper/tree/master/addons)。本次没有创建收录文件到外部仓库，也没有提交 PR。

## Zotero 中文社区插件索引

维护仓库为 [zotero-chinese/zotero-plugins](https://github.com/zotero-chinese/zotero-plugins)，网站入口为 [Zotero 中文社区插件合集](https://zotero-chinese.com/plugins)。其当前 README 已恢复新插件投稿，可提交 Issue 说明仓库、用途和发行下载地址，或在 `src/plugins.ts` 中按仓库名排序新增条目后发 PR。

当前源数据形式如下，**不是直接编辑生成的 `plugins.json`**：

```ts
{
  repo: 'zhangyehao/zotero-fulltext-assistant',
  releases: [],
  tags: ['attachment', 'integration'],
  discoverReleases: true,
}
```

`discoverReleases: true` 用于发现最近发行版中的最新正式版。需要保留旧 Zotero 版本时，在 `releases` 中维护已验证的历史标签与附件选择器；不能凭想当然填写兼容版本。

该仓库还会定时从 syt2 清单同步源数据并创建 PR，但同步不是自动审核合并。当前 README 描述了逐步恢复独立采集的 `shadow` / `primary` 流程：`shadow` 会生成候选数据和差异报告，对外索引仍可能沿用外部 scraper；网站何时切换独立数据源另行控制。因此，源条目合并、采集成功和网站实际展示应分别核实。

参考：[中文 README](https://github.com/zotero-chinese/zotero-plugins/blob/main/README-zh.md)、[源清单 src/plugins.ts](https://github.com/zotero-chinese/zotero-plugins/blob/main/src/plugins.ts)。当前仓库仍为私有，本文准备将来的收录路径，不表示已被任何市场收录。
