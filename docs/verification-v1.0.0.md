模拟 HTTP、合成 PDF 和 DOM 测试与真实网络结果分别记录。候选自身检查现有 latest，不等于公开升级通过。

原生验收在单独的测试 profile/data 中执行；启动器由显式 SHA-256 指定候选，运行前后检查安装包、实际资源路径与测试脚本摘要，命令和报告以本次 session/command 标识配对，拒绝旧报告。七组结果为：完成流程 35 项、包生命周期 66 项、下载流程 31 项、批次 48 项、更新 22 项、来源 18 项、原生界面 30 项，合计 **250 项全部通过**。来源组包含从官方 PMC 数据集下载真实 PDF、原生身份核对、隔离临时条目保存及再次核对；不使用真实 API key 或付费内容额度。界面组使用包内 UI、真实 Gecko 偏好设置文档和内存合成数据，结束后恢复原设置根节点，并检查真实任务关联和设置未改变。

更新组的超时、迟到回调、显式安装和摘要失败场景采用注入测试。候选自身检查现有公开更新源成功，不能据此宣称旧版已从公开源升级到 1.0.0。

原生 UI 在一次并发下载较重的执行中，固定等待 160 毫秒未能等到 120 毫秒防抖后的搜索渲染。验收脚本改为最多 5 秒的准确 DOM 条件轮询，保持目标条目、页大小及全部 30 项断言不变；运行时代码未因该等待问题改变。随后同一最终 XPI 的七组全部重跑通过。

重试或新增备用路径后的结果单独标明“首轮”“重试”及新增覆盖；同一篇不能因不同来源和多次下载重复算成功。测试期间代码、key、额度、网络或会话改变时分段报告，不能把不同条件直接合并成速度对比。

### 最终 1.0.0 联合来源与缓存抽样

最终 XPI 的 50 篇联合来源检查启用 OpenAlex、PMC / Europe PMC、CORE 和 Semantic Scholar，版本偏好为任意版本；关闭出版社、Zotero OA、自定义来源与两项托管内容开关，以检查普通 API 候选。每篇总时限为 60 秒，成功保存即停止剩余尝试。19 篇成功的最终发现渠道为 OpenAlex 10 篇、PMC 9 篇；这只是成功时的归属，不是四个提供方各自完整扫描后的覆盖率。

随后分别抽取 5 篇检查 CORE 官方托管和 OpenAlex 缓存；样本优先选旧版已有候选但未成功的文献，不是随机覆盖率调查。两项内容开关只在各自独立检查中开启，使用连续的本机持久计数，未清零额度：

| 独立检查 | 最终候选本轮结果 | 跨修复尝试的本机预留 |
| --- | --- | --- |
| CORE 官方托管，5 篇 | 3 次预留，0 篇保存；修复后的真实 302 正确跟随到 `core.ac.uk`，后续返回 403 人工验证；其余候选受本机上限、元数据无 PDF 或 DOI 不符等限制 | 之前 5 次受重定向问题影响，本轮再 3 次，累计 8 次；失败不返还 |
| OpenAlex 缓存，5 篇 | 2 篇核对保存，2 篇无缓存，1 篇受到本机额度限制 | 之前 3 次预留均保存成功，本轮再 2 次成功，累计 5 次预留/成功 |

本机预留不是网站扣费记录或 token 余额。CORE 和 OpenAlex 的服务余额、每次实际 token 成本未在本次取得，不能从这些次数推算。CORE 官方 API 可以返回网页跳转，配置 key 不保证直供 PDF，也不保证绕过后续人工验证；本次没有取得 CORE 托管 PDF，不把 302 或元数据成功记作全文成功。

最终候选还完成 8 个自定义端点 × 相同 5 篇，共 40 次检查：2 次核对保存、1 次待核对、37 次未取得候选文件。缓存和自定义检查属于分开的抽样/端点级结果，不与 50 篇联合来源成功数相加。最终报告没有未处理的执行或临时条目清理错误。

结束后已关闭来源基准的隔离进程，核对该临时文库条目数为 0，并清除为测试临时复制的登录凭据文件。诊断环境和不公开的逐篇原始报告继续保留本地，没有删除整个测试目录，也没有替换正式文库。
