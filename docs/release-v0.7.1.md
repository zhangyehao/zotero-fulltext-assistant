# 0.7.1 更新说明

本版修复已有科研通求助的任务无法重新检查本地下载、手动补录后缺少来源核验入口的问题，并增加网站最低悬赏选项。版本面向 Windows / Zotero 10.0.7，仓库和分发仍采用私有、草稿预发布流程。

## 界面与设置

当前横向标签为 **任务 / 设置 / 科研通设置 / 消息**：

| 标签 | 内容 |
| --- | --- |
| 任务 | 当前批次、跨批次未完成与完成历史、获取和核验操作、关联已有求助。 |
| 设置 | 简繁英界面语言、浏览器下载文件夹、机构登录保存状态。 |
| 科研通设置 | 账号登录、余额与签到、悬赏积分、自动接受网站最低悬赏积分、应助检查间隔、自动下载与本地支出统计。 |
| 消息 | 站内信、刷新入口与最近刷新时间。 |

悬赏积分和检查间隔的数字居中显示。切换标签和轮询刷新保留未保存的输入；切换语言立即保存语言本身，不替用户保存其他草稿。已有求助关联位于任务页，便于从任务直接选择对应文献。

## 网站最低悬赏

**自动接受网站最低悬赏积分** 默认关闭，点击 **保存设置** 后生效。

- 关闭：网站最低要求高于本次基础积分时停止并提示，不发布该求助。
- 开启：采用基础积分和网站已核实最低要求中的较高值，再检查实际金额、余额和提交条件。基础 10、最低 30 的任务以 30 积分提交，按钮标示“10 积分起”并提示可能上调。
- 任务获准求助时同时保存基础积分和最低价开关的快照。后续更改全局设置不改写已排队任务的授权或已发布求助的金额；未提交任务在明确重试时使用当时设置。
- 表单与提交阶段都校验最低值；无效金额、无法核实的规则或余额不足会停止。已经有提交记录或结果不确定时仍先核实原请求，不重复提交。

这项设置只影响新求助悬赏，不购买高速下载权益。文件下载继续优先使用账号当前已核实的免费高速线路，否则使用普通免费线路。

## DOI 查询与已发布求助核对

发布前的文献信息查询若返回另一 DOI、没有 DOI 或无法规范化的 DOI，错误提示分别显示条目与网站返回的证据；不会因为标题相似而放行，也不会把“查询失败”描述为已经发布。

提交后已经取得求助编号、但详情解析或 DOI／账号／金额核验失败时，单独保存该编号和安全的详情页链接，显示 **已发布求助待核对**，避免丢失可能已创建的请求。它暂不绑定文献，也不能用于自动下载或采纳。

**打开已发布求助核对** 仅打开这一详情页；**立即检查** 重新读取同一请求，验证当前账号归属和当前 Zotero 条目 DOI。用户核对出版社原文后自行修正条目、两端 DOI 确实一致时才关联并继续；不替用户改 DOI，不重复发布。待核对引用随任务持久保存，暂停后重试仍检查原请求；应先核实这个已发布记录，再切换其它获取方式，以免清除提交证据。退出账号、暂停或条目关联变化会阻止迟到的结果继续绑定。

## 求助之后下载到本地的文件

修复科研通下载页把长文件名显示为省略号时，正确文件被误报“下载页面文件名与应助文件不一致”的问题。页面保留完整 `title` 时核对完整名称，并验证截短正文确实属于该名称；没有完整名称、正文矛盾或节点重复仍停止。账号、文件编号、论文身份及完整 PDF 内容核验继续保留。

以前绑定求助会停止目录监控，而“检查已下载文件”又排除了已有求助的任务；手动选取匹配文件后记录为本地 PDF，已获取列表缺少重新核验网站文件的入口。

本版为已有求助的未完成任务提供 **检查已下载文件**。它重新检查配置目录中在任务创建后创建或修改的 PDF，保留求助编号和原悬赏，不重新打开页面或发布求助。检查目录期间暂停该任务的远端轮询；**立即检查** 切回科研通应助检查。旧轮询快照不会覆盖新启动的目录检查。

目录中明确匹配且唯一对应任务的 PDF 可自动入库。对已有求助任务使用 **选择已下载的PDF** 时，即使身份自动匹配，也要求先预览并明确确认。不同 DOI 等明确错篇证据仍会拒绝导入；人工确认不能覆盖这种冲突。

本地文件保存后，插件读取原求助的具体应助文件并核验：

1. 求助与论文身份对应，且当前账号可访问该文件。
2. 网站 PDF 与已保存附件的内容指纹完全一致，附件仍属于原文献。
3. 文件身份自动匹配，或这次本地导入已有绑定具体附件、指纹和文献的明确人工确认。

通过后才记录科研通来源、采纳具体文件并标记对应上传通知已读，不再导入一份附件，不改变原完成日期。旧历史没有人工确认凭据时，不能仅靠相同字节跳过论文身份核验。文件不一致、过期、无法访问或账号发生变化时保留已有全文和原来源，提示继续处理。

已获取且有关联求助、但没有核验凭据的任务现在提供 **核验科研通文件**，包括本地 PDF、浏览器下载等旧记录。仅存在求助编号并不证明文件来自该求助。关联科研通任务的本地导入也不再自动记为出版社或机构访问经验。

## 来源与积分

科研通来源旁显示已核实的任务实际金额：采纳完成时为 **已支出 N 积分**，尚未采纳时为 **悬赏 N 积分（待采纳）**。金额来自实际提交结果或网站具体求助记录，不使用当前默认设置推算。

旧记录只有本地默认值、缺少实际金额证据时显示 **积分待核实**。后续检查、文件核验或采纳响应提供可靠金额后更新记录。金额与核验状态随任务保存，改变全局积分、刷新列表或重启不会把历史支出替换成新的默认值。

**科研通设置** 新增支出统计：从本机保存的任务和采纳凭据中，汇总已采纳且金额已核实记录的积分总额、计入条数与平均每条积分，并展示最近 10 条支出明细。尚未采纳或积分待核实的记录不计入金额、条数及平均值，避免把预算当成已支付金额。该统计跨重启保留所依据的历史，反映插件本地记录范围，不是科研通账号的完整账单，也不表示当前账户余额。

## 每日签到提醒与只读核实

科研通设置增加默认启用的签到提醒。Zotero 运行、会话可用时，在本机时间每天 **06:00** 后检查当天签到状态；打开全文助手时可补查。Zotero 关闭期间不执行检查，之后启动或打开设置页时按当前状态补查，不为此创建系统定时任务。

签到按钮由用户在官方网站点击。插件只读取状态，在 **余额与签到** 区提供 **去网页签到** 入口；已确认签到时显示 **查看签到页面**，也可用 **刷新余额与签到** 手动核实。打开页面后短时复查，显示网站明确确认的签到结果、积分余额和可核实的奖励。不会发送自动签到请求或自动操作网页按钮，也不把打开页面、余额变化或预计奖励直接当成签到成功。

查询记录按账号保存到本机 `checkin-status.json`，退出或切换账号后不展示上一账号的余额。进入新一天时清除昨天的签到成功与奖励标记，旧余额只能作为上次查询值。普通补查至少间隔 2 分钟，错误后至少间隔 15 分钟自动重试；同一账号并发检查共用一次请求。关闭提醒停止自动检查，用户仍可自行打开官方网站或手动刷新。

## 检查边界

回归范围包括最低价开关与实际金额、重复提交保护、旧任务迁移、已关联求助的目录检查、人工确认、不同文件不归因、附件修改与账号退出的并发处理、签到只读查询与账号隔离、设置分类及简繁英界面。

网站提交、采纳和标记已读使用受控模拟响应验证。本轮不为测试在真实科研通发布新求助、采纳文件或消费积分。模拟结果不能替代将来的网页改版、真实验证码或机构认证验收。原生安装包检查、最终校验值及正式安装状态应以本版交付验收记录为准；本说明不提前声明这些步骤已完成。

旧版本的实测证据继续保留在 [0.7.0 验收记录](verification-v0.7.0.md) 和更早版本文档中，不计作本版重跑结果。
